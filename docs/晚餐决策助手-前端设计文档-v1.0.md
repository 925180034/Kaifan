## 1. 前端目标

前端的核心目标不是展示很多菜谱,而是让用户在下班前最累的时候,用 30-60 秒完成晚餐决定。

设计原则:

- **少思考**:首页直接给方案,不要让用户先搜索;
- **可执行**:每张卡都能继续走到菜谱、购物清单或平台搜索;
- **像生活工具**:安静、清楚、轻快,不要做成营销页;
- **移动优先**:默认在手机上使用;
- **反馈轻**:选择和饭后反馈都要一两下完成;
- **可迁移**:H5 组件结构为后续小程序复用留余地。

---

## 2. 信息架构

MVP 页面:

1. **欢迎页**:一句话说明价值,进入画像问卷;
2. **冷启动问卷页**:5 个必答问题;
3. **今日决策页**:主页面,展示今日状态、主推荐、三张方案卡;
4. **菜谱详情页**:查看自己做方案的完整步骤;
5. **购物清单页/抽屉**:勾选、复制、跳买菜搜索;
6. **设置页**:修改基础画像和深度画像;
7. **反馈弹窗**:饭后简单反馈;
8. **错误/空状态页**:生成失败、网络失败、深链失败时兜底。

P2 页面:

- 周菜单页;
- 历史记录页;
- 账单周报页;
- 冰箱食材页。

## 3. 全局导航设计

MVP 推荐底部 Tab:

| Tab | 页面 | MVP/P2 |
| --- | --- | --- |
| 今日 | 今日决策页 | MVP |
| 菜谱 | 最近菜谱/菜谱缓存 | P2 可完整化,MVP 可隐藏 |
| 设置 | 画像与偏好设置 | MVP |

MVP 最简可以只保留:

- 首页右上角设置按钮;
- 不做底部 Tab;
- 菜谱详情通过首页进入;
- 这样更轻,开发更快。

推荐 MVP 采用第二种:首页 + 设置入口,避免第一版像一个空壳 App。

## 4. 视觉风格

### 4.1 风格关键词

- 清爽;
- 温暖但不油腻;
- 像一个可靠的生活助手;
- 信息密度适中;
- 不做夸张美食社区感;
- 不做复杂营销视觉。

### 4.2 色彩建议

避免整页单一橙色或大面积渐变。建议使用中性色做底,用少量功能色区分三种方案。

| 用途 | 建议 |
| --- | --- |
| 页面背景 | `#F7F5F0` 或浅暖灰 |
| 主文本 | `#1F2933` |
| 次文本 | `#667085` |
| 自己做 | 绿色系点缀,表示新鲜/食材 |
| 点外卖 | 黄色或琥珀色点缀,表示快捷 |
| 出去吃 | 蓝色或青色点缀,表示出行 |
| 危险/禁忌 | 红色 |
| 成功/已选择 | 绿色 |

页面整体应像日常工具,而不是美食广告页。

### 4.3 字体与排版

- 移动端正文 14-16px;
- 卡片标题 18-22px;
- 首页主推荐标题 22-28px;
- 不使用过大的 hero 字;
- 数字信息如时间、价格、蛋白质可以更醒目;
- 所有按钮文字必须在小屏不换行或合理换行。

### 4.4 图标

建议使用图标帮助快速识别:

- 自己做:锅、餐盘、厨具;
- 外卖:外卖袋、骑手、闪电;
- 出去吃:地图、店铺、定位;
- 时间:时钟;
- 预算:钱包;
- 营养:叶子、哑铃或能量;
- 天气:云、雨、太阳;
- 换一批:刷新;
- 复制:复制图标;
- 跳转:外链图标。

后续开发如果使用 React,建议使用 `lucide-react`。

## 5. 页面设计

### 5.1 欢迎页

目标:让用户知道这不是菜谱大全,而是帮他今天做决定。

内容:

- 产品名:晚餐决策助手;
- 一句话:每天 30 秒,帮你决定今晚自己做、点外卖还是出去吃;
- 主按钮:开始设置;
- 次按钮:先随便看看;
- 轻提示:不需要注册,可以稍后修改偏好。

表现:

- 不做复杂 landing page;
- 不做长篇功能介绍;
- 第一屏直接进入使用。

### 5.2 冷启动问卷页

目标:30 秒内收集必要画像。

形式:

- 单页分步问卷,每次只看一个问题;
- 顶部进度条:1/5,2/5;
- 全部用点选标签或卡片;
- 最后一页按钮:生成今晚方案。

问题顺序:

1. 几个人吃?
2. 有什么忌口或过敏?
3. 吃辣程度?
4. 每人预算大概多少?
5. 今天/平时做饭意愿?
6. 可选:喜欢哪些口味?

交互细节:

- 多选题底部显示"下一步";
- 忌口页提供"没有忌口";
- 支持返回上一题;
- 用户跳过可给默认值,但过敏忌口建议明确选择。

### 5.3 今日决策页

这是 MVP 最重要的页面。

页面结构:

```text
顶部:
  今天日期 + 天气 + 设置入口

今日状态:
  偷懒 / 正常 / 想吃好点

主推荐:
  今晚最推荐: 自己做
  菜名/品类 + 关键理由
  [别问了,就这个]

三张方案卡:
  自己做
  点外卖
  出去吃

底部:
  换一批 / 反馈入口 / 最近吃过提示
```

主推荐模块:

- 永远展示系统排名第一的方案;
- 用一句话解释为什么;
- 主按钮进入履约;
- 用户不想被三张卡干扰时可以直接点。

三张方案卡每张必须展示:

- 类型标签;
- 标题;
- 预计时间或等待成本;
- 预计人均;
- 1 句推荐理由;
- 主要动作按钮;
- 次要动作:换这个方向。

### 5.4 自己做卡片

信息优先级:

1. 菜品组合;
2. 总耗时;
3. 人均成本;
4. 难度;
5. 营养亮点;
6. 缺哪些食材。

示例:

```text
自己做
番茄虾仁豆腐饭 + 拍黄瓜
25 分钟 · 约 ¥28/人 · 简单
你今天选了偷懒模式,这套不用复杂备菜,蛋白质也够。
[看菜谱] [换这个]
```

### 5.5 外卖卡片

信息优先级:

1. 推荐品类;
2. 搜索词;
3. 预算建议;
4. 推荐原因;
5. 跳转按钮。

示例:

```text
点外卖
热汤面 / 砂锅粥 / 轻食鸡胸饭
建议搜: 热汤面 少油 高评分
今晚有雨,外卖比出门更省心。
[去美团搜] [复制关键词]
```

### 5.6 出去吃卡片

信息优先级:

1. 推荐餐饮方向;
2. 适合场景;
3. 人均预算;
4. 搜索词;
5. 跳转按钮。

示例:

```text
出去吃
附近粤菜小馆
适合 2 人 · 人均 ¥80-120
你今天选择想吃好点,粤菜相对清淡,也不容易踩重油。
[去点评搜] [复制关键词]
```

### 5.7 菜谱详情页

页面结构:

- 顶部:菜名、收藏/反馈入口;
- 摘要条:耗时、难度、成本、热量/蛋白质;
- 食材区:可勾选,按分类展示;
- 步骤区:每步单独卡片,显示时间和要点;
- 翻车提醒:火候、调味、替代方案;
- 底部固定操作区:复制购物清单 / 去小象搜 / 做完了。

交互:

- 食材可勾选;
- 步骤可以逐步打勾;
- 购物清单可从底部抽屉打开;
- "做完了"打开反馈弹窗。

### 5.8 购物清单

建议做成底部抽屉,而不是单独页面,这样从菜谱回来更顺。

内容:

- 食材分类;
- 用量;
- 是否已拥有;
- 复制全部;
- 按单个食材复制;
- 跳小象搜索。

分组:

- 肉蛋奶;
- 蔬菜水果;
- 主食豆制品;
- 调料干货。

### 5.9 设置页

MVP 设置页内容:

- 基础画像;
- 忌口与过敏;
- 口味偏好;
- 预算;
- 做饭意愿;
- 常用平台;
- 清空本地数据。

P2 增加:

- 营养目标;
- 常备食材;
- 厨具;
- 提醒时间;
- 账单预算;
- 家庭成员。

### 5.10 反馈弹窗

触发时机:

- 用户选择方案后可延迟出现;
- 菜谱页点击"做完了";
- 第二天打开时询问昨天是否合适。

形式:

```text
昨晚这个方案怎么样?
[好吃,下次还吃] [太贵] [太麻烦]
[没吃饱] [太油/太咸] [不合口味]
```

不要强制填写长文本。可选备注放最后。

## 7. 状态设计

### 7.1 加载状态

场景:

- 首次生成方案;
- 换一批;
- 打开菜谱详情;
- 生成购物清单。

表现:

- 使用骨架屏,不要空白等待;
- 文案轻量:"正在想今晚吃什么";
- 超过 8 秒提示"有点慢,可以先用备用方案";
- 允许重试。

### 7.2 空状态

场景:

- 用户还没填写画像;
- 没有历史记录;
- 周菜单未生成。

表现:

- 给明确下一步按钮;
- 不写大段解释。

### 7.3 错误状态

场景:

- 网络失败;
- LLM 失败;
- 深链失败;
- 天气失败。

兜底:

- 网络失败:重试;
- 生成失败:使用备用方案;
- 深链失败:复制关键词;
- 天气失败:隐藏天气原因。

### 7.4 已选择状态

用户选择某张卡后:

- 卡片显示已选择;
- 其他卡弱化;
- 出现履约动作;
- 记录行为日志;
- 不要立即弹复杂反馈。

## 8. 交互细节

### 8.1 换一批

换一批分两种:

- 整体换一批:三张卡都更新;
- 单卡换一批:只换当前方向。

MVP 建议:

- 每张卡有"换这个";
- 页面底部有"全部换一批";
- 超过 3 次换一批后,提示用户选择不喜欢原因,用于画像修正。

### 8.2 不喜欢原因

用户换掉某个方案时,可轻量弹出:

- 不想吃这个;
- 太贵;
- 太麻烦;
- 太油;
- 最近吃过;
- 不符合忌口。

用户可以跳过。

### 8.3 平台跳转

点击跳转前:

- 先复制关键词到剪贴板;
- 再尝试打开平台链接;
- 失败时提示"关键词已复制,可以手动搜索"。

### 8.4 位置权限

MVP 不强制定位。推荐方案:

- 默认让用户手动选择城市/区域;
- 如果需要附近推荐,再请求定位;
- 拒绝定位也能使用,只是搜索词不带"附近"。

## 9. 响应式设计

### 9.1 移动端

目标宽度:

- 375px iPhone 基准;
- 360px Android 小屏可用;
- 430px 大屏舒适。

布局:

- 单列;
- 卡片纵向排列;
- 底部固定主操作;
- 问卷按钮底部固定;
- 抽屉高度不超过 80vh。

### 9.2 桌面端

桌面不是核心,但要可用:

- 页面最大宽度 480-560px;
- 居中显示手机宽度内容;
- 不拉成大横屏仪表盘;
- 方便开发调试和朋友在电脑打开。

## 10. 文案规范

### 10.1 语气

语气要像靠谱朋友,不要像营养专家训话,也不要像外卖广告。

推荐:

- "今晚有点适合吃热乎的。"
- "你今天选了偷懒模式,这个 20 分钟能搞定。"
- "这套比单点炸鸡更均衡一点。"

避免:

- "根据复杂算法为您精准匹配";
- "科学营养完美配比";
- "全网最好吃";
- "治疗控糖/减脂必备"。

### 10.2 按钮文案

| 场景 | 文案 |
| --- | --- |
| 主推荐采纳 | 别问了,就这个 |
| 自己做 | 看菜谱 |
| 外卖 | 去美团搜 |
| 出去吃 | 去点评搜 |
| 买菜 | 去小象搜 |
| 复制 | 复制关键词 / 复制清单 |
| 换一批 | 换这个 / 全部换一批 |
| 反馈 | 做完了 / 昨天还行吗 |

## 12. 前端埋点

MVP 需要记录的事件:

| 事件 | 触发 |
| --- | --- |
| `onboarding_started` | 开始问卷 |
| `onboarding_completed` | 完成问卷 |

| `card_selected` | 选择某张卡 |

| `feedback_submitted` | 提交反馈 |

埋点目标不是做复杂增长分析,而是判断推荐是否真的被采纳。

## 13. 可访问性与易用性

- 所有按钮点击区域不小于 44px;
- 文本与背景保持足够对比度;
- 图标按钮必须有文字或可访问标签;
- 不用颜色作为唯一状态表达;
- 加载和错误都有明确文案;
- 小屏下不出现横向滚动;
- 底部固定按钮不遮挡内容。

---

## 14. MVP 前端验收标准

页面验收:

- 首次打开能完成问卷并生成方案;
- 首页 375px 宽度下不卡、不挤、不横向滚动;
- 三张方案卡信息能快速扫描;
- 点击自己做能进入菜谱详情;
- 购物清单能复制;
- 外卖/点评/小象跳转失败时能复制关键词;
- 换一批有加载态和结果;
- 反馈能提交;
- 设置页能修改基础画像。

体验验收:

- 用户 60 秒内能完成一次晚餐决策;
- 首页不需要用户先搜索;
- 没有注册墙;
- 没有长篇说明;
- 弱网和生成失败时有备用方案。

## 15. 后续小程序迁移注意点

为了后续迁移小程序,前端应提前注意:

- 业务组件不要依赖浏览器特有 API;
- 平台跳转能力封装成 `platformLinkService`;
- 存储能力封装成 `storageService`;
- 分享能力封装成 `shareService`;
- 请求层独立封装;
- UI 组件尽量保持简单,避免过度依赖复杂 DOM 能力;
- 设计尺寸以移动端为基准。
